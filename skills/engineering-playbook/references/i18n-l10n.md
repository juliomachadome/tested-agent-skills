# Internationalisation and localisation (i18n / l10n)

i18n makes code able to serve any locale; l10n supplies the content for one. Tags: **[F]** read this pass, **[M]** model judgement. Project conventions win. Money, time zones and Unicode text rules are in `money-time-text.md`; do not repeat them.

## 1. Messages, not fragments
- Never build sentences by concatenation. Translators need the whole message so they can reorder parts; fragments are untranslatable alone **[F]**. Put every variable in one pattern with placeholders.
- ICU MessageFormat: `{name}` placeholders, `plural` and `select` arguments, `=N` exact matches, `offset`, and `other` is always required **[F]**. Nest `select` outside and `plural` inside, and write a full sentence in each branch **[F]**.
```
{count, plural, =0 {No messages} one {# message} other {# messages}}
{gender, select, female {She replied} male {He replied} other {They replied}}
```
- Quoting: apostrophes can start quoted text; use the typographic apostrophe in human text **[F]**.
- Do not use the legacy `choice` argument **[F]**. Do not build plurals as `count === 1 ? ... : ...`.

## 2. Plurals and gender (CLDR)
CLDR has six categories: zero, one, two, few, many, other; `other` is mandatory and is the fallback **[F]**. English needs one and other; Russian uses one, few, many and other **[F]**; Arabic and Polish need more than English (categories not on the page read; check the CLDR plural chart per language) **[U]**. A category depends on the number's required phrase form, not on grammar rules you can guess **[F]**. Give translators every category their language needs; `Intl.PluralRules` returns the category at runtime. Use `selectordinal` or `PluralRules({type:'ordinal'})` for "1st, 2nd". Gender is a `select` with an `other` branch; avoid asking users for gender just to inflect text.

## 3. Dates, numbers, currencies, lists
Use the `Intl` API with the user's locale, never hand-built formats: `DateTimeFormat`, `NumberFormat`, `PluralRules`, `RelativeTimeFormat`, `ListFormat`, `Collator`, `Segmenter` **[F]**. Output differs by locale (24.5.2012 vs 5/24/2012; 26.254,39 vs 26,254.39) **[F]**. `NumberFormat` with `style: 'currency'` and an ISO 4217 `currency` formats the symbol and placement; the locale is not the currency (a German user can see dollars) **[M]**. Sort with `Collator`, not `<`. Count characters with `Segmenter`, not `.length`. Pass the user's languages, with fallback, rather than a fixed `en-US` **[F]**.

## 4. Time zones
Store UTC instants, format in the viewer's zone, and set `timeZone` (an IANA name) explicitly in `DateTimeFormat` when the zone is the event's, not the viewer's **[M]**. Daylight-saving and recurring events: see `money-time-text.md`.

## 5. RTL layout
- Set `<html lang="ar" dir="rtl">`; `lang` does not give direction, so declare `dir` too **[F]**. Do not set base direction with CSS in HTML pages **[F]**.
- Use CSS logical properties: `margin-inline-start`, `padding-block`, `inset-inline-end`, `border-inline-start`, so one stylesheet works both ways **[F]** (the MDN overview defines block and inline; the examples are general knowledge **[M]**). Flex and grid order follow direction.
- User-generated text: `dir="auto"` on inputs and text areas, `<bdi>` around inserted values of unknown direction; `dir="auto"` can misread mixed text **[F]**.
- Flip directional icons (arrows, back, progress) but not logos, clocks, media controls or numerals' digits. Test with real Arabic or Hebrew, not just mirrored English.

## 6. Text expansion, fonts and scripts
Plan for longer text (German and Finnish often grow 30% or more; short UI strings grow more) **[M]**: no fixed-width buttons, allow wrapping, test with pseudo-locale. CJK text is shorter but taller; line breaking has no spaces, so use `Segmenter` and `word-break` carefully. Fonts: pick families that cover the scripts, subset per locale, use `unicode-range`, and set `font-family` fallbacks per `:lang()`. Avoid text in images. Never truncate by byte count. Normalise input (NFC) before comparing.

## 7. Translation workflow
- Keys: stable semantic keys (`checkout.pay_button`), not the English text; one message per key; never reuse a key for two meanings.
- Context for translators: a description, screenshot, max length, placeholder meaning and plural note per key. Without context, "Book" is a noun or a verb.
- Pseudo-localisation in CI: wrap text in accents and padding (`[Ĥéļļö ~~~~]`) to find hard-coded strings, truncation and encoding bugs before any translation exists **[M]**.
- Continuous localisation: extract keys on commit, sync with the translation tool, fail the build on missing keys or invalid ICU syntax, fall back to the default language, never ship an untranslated key to users.
- Next.js: detect locale from `Accept-Language`, route by sub-path (`/fr/products`) or domain, nest routes under `app/[lang]`, load dictionaries server-side so they do not enlarge client bundles, `generateStaticParams` for static pages, and set `<html lang>` **[F]**. Validate the `lang` param and `notFound()` for unsupported ones **[F]**.
- Let users change language manually and remember it; do not rely on IP.

## 8. SEO for languages
`hreflang`, per-locale canonical URLs, localised metadata and sitemaps are routed to `skills/seo-geo` (multilingual section). Do not auto-redirect crawlers by Accept-Language **[M]**.

## 9. Testing
Pseudo-locale and an RTL locale in the e2e run; unit-test plural branches for the languages you ship (including zero and fractions); snapshot long German strings for overflow; test timezone and DST boundaries; lint for string concatenation and hard-coded literals; check missing keys in CI; review one screen per locale with a native speaker before launch. A11y: `lang` per page and per foreign phrase (`lang` attribute on inline quotes) helps screen readers **[M]**.
