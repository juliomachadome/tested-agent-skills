# Technical SEO

Sources: Google Search Central pages (JavaScript SEO basics, link best practices, A/B testing, Core Web Vitals, canonical, sitemaps, localized versions, SEO Starter Guide), Bing Webmaster Guidelines (Feb 2026 coverage), Next.js docs 16.4. Read 12/11/2026 unless marked (not re-read).

## Crawling, canonical, sitemap, language, performance
- **[C] AI Overviews and AI Mode need only an indexed, snippet-eligible page.** Allow crawling in robots.txt, CDN and hosting; important content in text; internal links to it.
- **[C] Server-render or prerender everything indexable.** Google processes JS in three phases (crawl, render queue, index) and still says server rendering is a good idea because "not all bots can run JavaScript". [M] In Dec 2024 none of the measured AI crawlers (OpenAI, Anthropic, Perplexity, Meta, ByteDance) executed JS; only Google-infrastructure crawlers and Applebot did. May have changed; complete initial HTML covers every case.
- **[C] Canonical:** redirects and `rel="canonical"` are strong signals, sitemaps weak; canonical is a hint. Absolute URL, one tag, present in initial HTML (never swapped by JS), internal links pointing to the canonical. Never canonicalise with robots.txt or `noindex`.
- **[C] A/B tests:** a variant on its own URL carries `rel="canonical"` to the original, "rather than a noindex meta tag"; redirect to variants with 302, not 301; never show Googlebot a different URL set than people; end tests and remove URLs and scripts once data is in. Googlebot generally does not send cookies, so in cookie-based tests it sees the refuser's version. Button colour/size/position/text changes have little or no effect on snippets and ranking.
- **[C] Sitemap:** only canonical absolute URLs; `lastmod` used only if consistent and verifiable and reflecting significant change; `priority` and `changefreq` ignored; 50 MB or 50k URLs per file. (not re-read)
- **[C] hreflang:** one method (HTML, HTTP header or sitemap); each version lists itself and all others; no return link = ignored; absolute URLs; `x-default` fallback; ISO 639-1 (+ ISO 3166-1) codes. Google does not use hreflang or `lang` to detect language. Never redirect by IP or browser language: Googlebot crawls without `Accept-Language`, mostly from the US. (not re-read)
- **[C] Core Web Vitals "good":** LCP ≤ 2.5 s, INP < 200 ms, CLS < 0.1; Google "highly recommends" them. [M] Weight unknown; treat as mandatory hygiene, not a ranking lever.
- **[C] Titles, descriptions, URLs:** unique, clear, accurate title per page; short unique meta description (Google sometimes uses it, usually builds the snippet from content); short descriptive `alt`, image near related text; keywords in URLs have almost no effect; hyphens, not underscores (clarified 23/10/2026).
- **[C] Headings:** order and count do not matter for ranking; they matter for screen readers and reading.
- **[C] Bing:** `NOARCHIVE` blocks use in Copilot answers and grounding; `NOCACHE` limits Copilot to URL, title and snippet; `NOSNIPPET`/`data-nosnippet` can hurt citation. Never on pages you want cited.

## Internal links and architecture
- **[C] Google reliably follows only `<a href="…">`.** Buttons with `onclick`, `javascript:` links or routing without `href` do not count; links inserted by JS count if they are normal anchors.
- **[C] Every page you care about needs a link from at least one other page.** No ideal number of links. A new page gets, the same day, a link from at least one older page that already gets visits.
- **[C] Good anchors are descriptive, reasonably short and make sense alone.** "Click here" is bad; forcing keywords into anchors is stuffing.
- **[C] Linking out to sources does not hurt.** `nofollow` only for untrusted sources; `sponsored` for paid; `ugc` for user-inserted.
- **[F] Practitioner habits, no official weight:** pillar page linking all children and children linking back; in-body links where the reader wants more, besides "related" lists; no indexable page more than 3 clicks from home. Sensible for readers and for query fan-out; promise no measured gain.
- **[C] Faceted navigation, internal search and tracking parameters do not create indexable URLs:** canonical to the clean version, kept out of the sitemap. Removed pages return 404/410 or 301 to a real replacement; never 200 with "not found" (soft 404).

## Next.js App Router (docs 16.4; check other versions)
- **[C] Indexable content in Server Components, prerendered wherever possible** (`generateStaticParams`, ISR). Initial HTML carries text, links, metadata and JSON-LD; interactivity goes in Client Components inside the page.
- **[C] Metadata via the Metadata API** (`metadata`/`generateMetadata`, Server Components only). `metadataBase` in the root layout; `alternates.canonical` and `alternates.languages` per page; metadata files (`opengraph-image`, `icon`) take priority over the object.
- **[C] Layout/page merge is shallow:** a page defining `openGraph`, `robots` or `alternates` replaces the layout's whole object. Two common bugs: canonical in the root layout inherited by every page (all pointing home); partial `openGraph` on a page erasing inherited image and description. Rule: canonical always per page; nested objects built by a shared function.
- **[C] Streaming metadata (since 15.2):** on **dynamic** pages Next may send UI before `generateMetadata` finishes and append tags in `<body>`; for "HTML-limited bots" it waits and puts them in `<head>`. The default list covers Bingbot, Yandex, Baidu, DuckDuckBot, Applebot, bots with "Google-" in the name and social preview bots; Googlebot gets streaming (Next says it verified Googlebot reads the tags). **It does not cover GPTBot, OAI-SearchBot, ClaudeBot or PerplexityBot.** Prerendered pages ship everything in `<head>` for all. If an indexable page must be dynamic, add those bots to `htmlLimitedBots` in `next.config`.
- **[C] Status codes:** `notFound()` before streaming starts returns 404; after, the response stays 200 with the not-found UI and a `noindex` meta. For a real 404, check existence before any `Suspense`/`loading`. In static routes `dynamicParams = false` returns 404 outside `generateStaticParams`; `redirect()` is temporary (307), `permanentRedirect()` or `redirects` with `permanent: true` are permanent (308). (not re-read)
- **[C] `app/sitemap.ts` and `app/robots.ts`** generate the files; sitemap with canonicals and true `lastModified` only; `changeFrequency`/`priority` exist in the type but Google ignores them; above 50k URLs use `generateSitemaps`. (not re-read)
- **[C] JSON-LD** as `<script type="application/ld+json">` rendered in the page's Server Component, with `JSON.stringify` and `<` escaped as `<` to prevent HTML injection; one `@graph` for linked nodes. [M] Server Component output also travels in the RSC payload, so large JSON-LD weighs twice: keep schema lean on weight-budgeted pages.
- **[C] Images with `next/image`** (alt, dimensions, priority on the LCP image); fonts via `next/font`. Media that must be indexed is not behind auth or blocked in robots. (not re-read)
- **[C] Multiple languages:** one URL per language (subpath), `alternates.languages` listing all versions plus `x-default`, no automatic language redirects for bots. A page existing in one language declares no hreflang to missing versions.
- **[C] A/B in Next:** cookie-chosen variant with `rewrite` in the proxy (formerly middleware) keeps the URL; Googlebot sends no cookie and sees the control, which Google accepts. A variant with its own URL: canonical to the original, **no** `noindex`, out of the sitemap, no internal links. Remove flag and routes when done.
- **[C] Preview and staging out of the index** via `X-Robots-Tag: noindex` header or authentication (some hosts do this for preview deploys). Check production did not inherit the header and the test domain does not appear in canonical, sitemap or Open Graph.
- **[M] Lighthouse SEO audits on `noindex` staging** drop the score without a real problem: measure in production or locally in production mode.
