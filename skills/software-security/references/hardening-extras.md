# Hardening extras (gap pass 15/11)

Format: **rule** · why · source id (see `sources.md`). Ten additions; ideas cross-checked against an external knowledge base (AGPL), rewritten.

1. **Never merge untrusted JSON into objects with a recursive merge or deep-clone helper that accepts `__proto__`, `constructor` or `prototype` keys.** One polluted prototype changes behavior for every object in the process (authorization flags, template options). Use `Map`/`Set` for key-value data from users, `Object.create(null)` for dictionaries, and consider Node's `--disable-proto=delete` as defense in depth. · W50
2. **Edge proxy and origin must agree on where a request body ends.** Reject, do not forward, a request carrying both `Content-Length` and `Transfer-Encoding`; close the connection after answering; keep proxy and origin HTTP libraries patched, and prefer HTTP/2 or HTTP/3 end to end where the platform allows. Disagreement on framing is how a second, hidden request reaches the origin. · W51
3. **Pin the trust policy of OIDC federation (CI to cloud) to one repository, one ref or environment and one audience.** The cloud checks token claims against the conditions you configured; a wildcard subject (`repo:org/*`) trusts every workflow in the organization, which equals publishing the credential. Re-check the conditions when the provider changes its subject-claim format. · W52 (claim checking), engineering judgment (wildcard consequence)
4. **Ship a VEX statement next to the SBOM when you suppress a scanner finding.** "Not affected" with a justification (component not present, vulnerable code not reachable) is auditable; a silent ignore-list entry is not. Review the statements when the dependency version changes. · W53, W22 (prioritization)
5. **Verify, do not only produce, provenance.** The deploy step (or cluster admission) checks the artifact's signature and build provenance against an expected builder and source repository before running it; a build that signs but a deploy that never verifies protects nothing. · W20
6. **Rehearse rotation before you need it.** Rotate each machine secret once on a quiet day with an overlap window (old and new valid together), prove consumers picked up the new value, then revoke the old. Prefer credentials issued per consumer with a short lifetime over one long-lived shared secret. · W11
7. **Incident evidence first by volatility, then by convenience.** Capture what disappears first (running processes, open connections, memory-resident state, container filesystem) before restart or redeploy, then logs and disk; hash copies and record who collected what and when. Containment still comes first; a snapshot before the restart costs minutes. · W54, W24
8. **A security gate must be able to reject.** Write per gate what "fail" means (new critical finding, unsigned artifact, secret detected), who may grant an exception, and when it expires; an exception without owner and expiry date is a permanent suppression. · W19 (PW, PS), W48
9. **Function-style and queue-driven code: one role per function, a concurrency cap, a spend alert, and every event treated as untrusted input.** Queue messages, storage notifications and webhooks are written by someone else; unbounded concurrency or recursion is both a denial-of-service and a bill. · W55, W1 (A06 insecure design)
10. **Access follows people, not projects.** On role change or departure revoke production, database, DNS and CI access the same day; review who holds each every quarter (a short table is enough); keep one sealed break-glass credential, tested twice a year and rotated after each use. · W19 (PO.5), W11
